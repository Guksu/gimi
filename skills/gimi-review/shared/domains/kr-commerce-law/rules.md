# 분야 프리셋 — `kr-commerce-law` (국내 전자상거래·개인정보 법령)

국내 전자상거래·개인정보 법령이 코드에 직접 요구하는 것이다. 설정 `.agents/gimi.json`의 `presets`에 `kr-commerce-law`를 넣으면 리뷰(gimi-review)가 쓴다. 형식은 `commerce` 프리셋과 같다.

**이 프리셋은 법률 자문이 아니다.** 법령·고시가 코드에 직접 요구하는 것만 골라 조문과 함께 적었다. 팀이 조문을 확인하고, 회사의 해석이 다르면 회사 규칙의 `## 끈 프리셋 규칙` 절에 `- KCL-006 — 이유`처럼 적어 끄거나 회사 규칙으로 바꾼다.

## 기준 버전

조사일 2026-10-19. 국가법령정보센터의 현행 본문으로 확인했다. 법이 바뀌면 이 표를 먼저 고친다.

| 법령·고시 | 기준 |
|---|---|
| 전자상거래 등에서의 소비자보호에 관한 법률(전자상거래법) | 2026.7.21 시행, 법률 제21312호 |
| 개인정보 보호법 | 2026.9.11 시행 |
| 전자상거래 등에서의 소비자보호 지침 | 공정거래위원회고시 제2025-8호, 2025.10.24 시행 |
| 개인정보의 안전성 확보조치 기준 | 개인정보보호위원회고시 제2026-9호, 2026.7.1 시행 |

## 해석이 들어간 값

경계값 중 조문에 숫자가 그대로 있지 않고 해석이 들어간 것에는 **(해석 — 팀 확인 필요)**를 붙였다. 이런 값은 회사 설정에서 정한다.

```json
{
  "kcl": {
    "periodCounting": "civil-code",
    "businessDays": "docs/gimi/business-days.json"
  }
}
```

| 항목 | 뜻 | 설정하지 않으면 |
|---|---|---|
| `kcl.periodCounting` | 청약철회 기간을 세는 방식. `"civil-code"`는 민법의 기간 계산(첫날 제외, 말일이 토요일·공휴일이면 다음 날 만료). 다르게 보면 `"custom"`으로 두고 회사 규칙에 적는다 | 리뷰는 기한 계산을 단정하지 않고 "확인 질문"으로 올린다 |
| `kcl.businessDays` | '영업일' 달력(휴무일 목록). 법에 '영업일' 정의가 없다 | 리뷰는 영업일 계산을 "확인 질문"으로 올린다 |

## 청약철회·환불

## KCL-001 청약철회 기한은 서버 함수 하나에서 계산한다
- 대상: 둘 다(판정은 백엔드, 프론트는 서버가 준 마감 시각을 표시)
- 왜: 반품 버튼이 배송 완료 5일 뒤 닫혀 6일째 고객의 철회를 막는다. 법정 기간을 줄여 표시한 것이 된다
- 대신: 계약 내용 서면을 받은 날(공급이 더 늦으면 공급받은 날)부터 7일로 계산한다. 표시·광고와 다르면 공급받은 날부터 3개월 또는 그 사실을 안 날부터 30일이다. 사유별로 기한을 나눈다
- 확인: 7보다 작은 기한 상수(`RETURN_DAYS = 5`), 클라이언트에서 한 기한 비교, 서면 수령일과 배송 완료일 중 늦은 날을 쓰지 않음. 의도 — 사유별 분기
- 경계값:
  - 프론트: 서버가 준 마감 시각 표시
  - 백엔드: 7일째 23:59(KST) 허용·8일째 00:00 차단, 7일째가 토요일·공휴일이면 다음 날까지 **(해석 — 팀 확인 필요: 민법 기간 계산 적용)**, 표시와 다름 사유의 3개월·30일
- 근거:
  - 전자상거래법 제17조①③ https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률/제17조
  - 소비자보호 지침 Ⅱ — 기간을 줄여 게시하면 위반이라는 예시 https://www.law.go.kr/행정규칙/전자상거래등에서의소비자보호지침
  - 민법 제157조(제159·161조) — 첫날 불산입, 말일이 토요일·공휴일이면 다음 날 만료 https://www.law.go.kr/법령/민법/제157조

## KCL-002 '반품 불가'는 상품 화면에 표시한 경우에만 적용한다
- 대상: 둘 다
- 왜: 상세 화면에 아무 표시가 없던 개봉 상품을 반품 불가로 거절한다. 표시가 없으면 예외를 주장할 수 없다
- 대신: 반품 불가 판정은 그 상품에 철회 불가 표시가 있었는지(또는 시험용 상품을 줬는지)를 조건으로 한다. 주문제작은 미리 별도로 고지하고 동의를 기록한다. 디지털콘텐츠는 제공 개시 시각을 기록한다
- 확인: 영향 범위 — `isReturnable` 판정과 상품 화면 표시가 같은 값에서 나오는가
- 경계값:
  - 프론트·백엔드: 표시 있음/없음 × 개봉/미개봉, 디지털콘텐츠 미개시분
- 근거:
  - 전자상거래법 제17조②⑥
  - 전자상거래법 시행령 제21조 — 주문제작은 별도 고지 + 서면(전자문서 포함) 동의 https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률시행령/제21조

## KCL-003 환불 기한과 공제 항목은 사유별로 서버에서 계산한다
- 대상: 백엔드
- 왜: 단순 변심 환불에서 반품 처리비까지 빼거나, 상품을 돌려받고 일주일 뒤에 환불한다
- 대신: 돌려받은 날부터 3영업일 안에 환급한다(카드는 지체 없이 결제업자에 취소를 요청). 단순 변심의 반환 비용은 소비자가, 표시와 다름의 반환 비용은 사업자가 낸다. 반환 배송비 말고 취소 수수료·위약금을 받지 않는다. 늦으면 지연배상금을 계산한다
- 확인: `refund = paid - restockingFee`, 사유별 분기 없음, 영업일 마감 추적 없음, 카드 결제를 PG 취소가 아닌 방법으로 환불
- 경계값:
  - 백엔드: 3영업일째·4영업일째 **(해석 — 팀 확인 필요: 영업일 달력 `kcl.businessDays`)**
- 근거:
  - 전자상거래법 제18조②③⑨⑩ https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률/제18조
  - 전자상거래법 시행령 제21조의3 — 지연배상금 연 100분의 15
  - 소비자보호 지침 Ⅱ(반환 배송비 외 수수료 금지)·Ⅲ1가(표시와 다르면 구매 배송비도 환불 권고)

## KCL-004 결제한 뒤 공급할 수 없게 되면 지체 없이 알리고 3영업일 안에 환급한다
- 대상: 백엔드
- 왜: 결제 뒤 품절된 주문이 '입고 대기'로 2주 동안 방치된다
- 대신: 품절로 바뀌는 상태 전이에 알림과 환급 마감 타이머·자동 취소 작업을 붙인다
- 확인: 영향 범위 — 품절로 바뀌는 상태 전이(`commerce` COM-013)
- 경계값:
  - 백엔드: 결제 후 3영업일째·4영업일째 **(해석 — 팀 확인 필요: 영업일)**
- 근거:
  - 전자상거래법 제15조①② https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률/제15조

## 표시·동의

## KCL-005 결제 직전에 확인 화면을 두고, 결제 동의 체크는 비워 둔다
- 대상: 프론트
- 왜: 결제 동의가 미리 체크된 원클릭 구매가 된다
- 대신: 상품·총액·제공 기간(구독)을 보이고, 정정·취소할 수 있는 단계를 둔다. 동의 체크 초기값은 비워 둔다
- 확인: 결제 동의의 `defaultChecked`·`useState(true)`. 의도 — 주문 요약의 총액·기간
- 경계값:
  - 프론트: 첫 진입 때 체크 상태, 정정한 뒤 다시 확인
- 근거:
  - 전자상거래법 제7조·제8조②·제14조②
  - 전자상거래법 시행령 제9조 — 미리 동의로 표시한 확인 절차 금지 https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률시행령/제9조

## KCL-006 첫 화면 가격은 필수 비용을 포함한 총금액으로 보인다
- 대상: 둘 다(가격 API도 총액 필드를 준다)
- 왜: 목록에는 9,900원인데 결제 단계에서 기본 배송비 3,000원이 처음 붙는다
- 대신: 목록·검색·홈의 첫 가격은 지불을 거부할 수 없는 비용의 합계다. 빼는 항목은 그 사유를 첫 화면에 알린다(특급배송비·제주·도서산간 추가비는 뺄 수 있다). 할인 조건이 있으면 첫 화면에는 할인 전 가격을 보이라는 권고가 있다
- 확인: 영향 범위 — 상품 카드가 쓰는 가격 필드
- 경계값:
  - 프론트: 기본 배송비가 있는 상품의 목록 금액
  - 백엔드: 총액 필드 계산
- 근거:
  - 전자상거래법 제21조의2①1호(2025.2.14 시행) https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률/제21조의2
  - 전자상거래법 시행규칙 제11조의4 — 뺀 항목과 사유를 알리는 방법
  - 소비자보호 지침 Ⅱ12(첫 화면·총금액의 뜻)·Ⅲ7가(할인 전 가격 권고)
- 확인하지 못한 것: 조건부 무료배송을 첫 화면 총금액에 어떻게 반영할지는 지침에 예시가 없다

## KCL-007 추가 상품은 미선택이 기본이고, 거부는 한 번이면 되고, 해지는 가입보다 어렵지 않다
- 대상: 둘 다(해지 API 포함)
- 왜: 연장보증이 체크된 채 결제된다. 거부한 뒤에도 같은 팝업이 반복된다. 가입은 앱에서 하는데 해지는 전화로만 된다
- 대신: 부가상품·멤버십 체크 초기값은 비운다. 거부하면 다시 묻지 않는다(처음부터 '7일간 보지 않기'를 줬다면 7일 뒤). 가입한 같은 웹·앱 안에서 해지할 수 있게 한다. 탈퇴 버튼은 로그인 첫 화면이나 거기서 한 번 눌러 가는 화면에 둔다(공정위 권고)
- 확인: 부가상품 체크 초기값 true. 리뷰 — 거부 선택지만 작고 흐림, 해지 재확인 2번 이상, 탈퇴 버튼이 엉뚱한 메뉴에
- 경계값:
  - 프론트: 거부한 뒤 두 번째 요구, '7일간 보지 않기' 6일째 재노출
- 근거:
  - 전자상거래법 제21조의2①2~5호, 시행령 제27조의2(7일)
  - 소비자보호 지침 Ⅱ13·14 — 가입한 같은 웹·앱 안에서 해지
  - 공정위 다크패턴 가이드라인 보도자료(2026.10.6) https://www.ftc.go.kr/www/selectBbsNttView.do?key=12&bordCd=3&nttSn=48089
- 확인하지 못한 것: 가이드라인 첨부 파일(13개 유형 세부)은 열지 못했다

## KCL-008 정기결제 금액 인상과 유료 전환은 30일 안에 받은 별도 동의로만 청구한다
- 대상: 백엔드
- 왜: 무료 체험 종료 작업이 가입 때 받은 포괄 동의만으로 결제한다
- 대신: 전환 일시·변경 전후 가격·결제 방법에 대한 동의 기록을 확인한 뒤 청구한다. 동의가 없으면 종전 가격을 유지하거나 해지한다
- 확인: 동의 레코드 확인 없는 청구, 동의가 없을 때의 분기 없음
- 경계값:
  - 백엔드: 전환 30일 전 안에 받은 동의, 31일 전 동의, 가입 때 포괄 동의
- 근거:
  - 전자상거래법 제13조⑥
  - 전자상거래법 시행령 제20조의2 — 전환 전 30일 https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률시행령/제20조의2
  - 소비자보호 지침 Ⅱ8 — 포괄 동의는 동의로 보지 않는다
  - 여신전문금융업감독규정 제24조의14 — PG는 승인 요청 7일 전까지 고지하는 방안 마련 https://www.law.go.kr/행정규칙/여신전문금융업감독규정

## KCL-009 법정 표시 사항은 공통 컴포넌트로 보인다
- 대상: 프론트
- 왜: 푸터를 고치면서 사업자등록번호·호스팅 사업자가 빠진다
- 대신: 사업자 정보와 공정위 사업자정보 공개페이지 링크, 주문서의 철회 기한·방법, 미성년자 주문에 법정대리인이 동의하지 않으면 취소할 수 있다는 고지를 공통 컴포넌트로 둔다
- 확인: 영향 범위 — 푸터·주문서 컴포넌트를 바꾼 diff
- 경계값:
  - 프론트: 만 19세 생일 전날·당일 회원의 주문서
- 근거:
  - 전자상거래법 제10조①, 시행령 제11조의4, 시행규칙 제7조 — 사업자 정보 표시와 공개페이지 링크 https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률/제10조
  - 전자상거래법 제13조②③ — 거래조건 표시, 미성년자 취소권 고지 https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률/제13조
  - 민법 제4·5조 — 19세 성년, 동의 없는 미성년자의 법률행위는 취소할 수 있다 https://www.law.go.kr/법령/민법/제5조

## 개인정보·보안·광고

## KCL-010 탈퇴해도 거래기록은 분리 보존하고, 기간이 끝나면 복원할 수 없게 파기한다
- 대상: 백엔드
- 왜: 탈퇴하자마자 주문을 지워 분쟁 때 증빙이 없다. 반대로 기한 없이 영구 보관한다
- 대신: 보존 테이블·만료일·파기 작업을 둔다
- 확인: 탈퇴 처리의 `DELETE orders`, 만료일 컬럼·파기 작업 없음
- 경계값:
  - 백엔드: 표시·광고 기록 6개월, 계약·청약철회 기록 5년, 결제·공급 기록 5년, 불만·분쟁 기록 3년
- 근거:
  - 전자상거래법 시행령 제6조 https://www.law.go.kr/법령/전자상거래등에서의소비자보호에관한법률시행령/제6조
  - 개인정보 보호법 제21조①③ — 지체 없이 파기, 법령상 보존할 것은 분리 저장 https://www.law.go.kr/법령/개인정보보호법/제21조
  - 개인정보 보호법 시행령 제16조 — 복원할 수 없게 삭제
- 확인하지 못한 것: '1년 미이용 회원 분리·파기'(시행령 제48조의5)는 2023.9.12에 삭제돼 지금은 법정 의무가 아니다

## KCL-011 마케팅 동의는 따로 받고, 거부해도 가입·구매를 막지 않는다
- 대상: 둘 다
- 왜: 마케팅 수신에 동의하지 않으면 가입 버튼이 눌리지 않는다
- 대신: 필수·선택 동의를 나눈다. 선택 동의를 거부해도 진행된다. 만 14세 미만은 법정대리인 동의를 받는다. 주민등록번호는 받지 않는다
- 확인: 필수 동의 묶음 안의 마케팅, 마케팅 미체크 시 비활성 버튼, 주민등록번호 입력칸, 14세 미만을 가르는 분기 없음
- 경계값:
  - 프론트·백엔드: 만 14세 생일 전날(법정대리인 동의 필요)·당일
- 근거:
  - 개인정보 보호법 제22조①7호·⑤, 제22조의2, 제24조의2①③ https://www.law.go.kr/법령/개인정보보호법/제22조

## KCL-012 결제·인증 정보는 암호화해 저장하고, 접근을 기록한다
- 대상: 백엔드
- 왜: 에러 로그에 카드번호가 평문으로 남고, 관리자 조회 기록이 없다
- 대신: 비밀번호는 일방향 암호화, 카드·계좌번호는 암호화해 저장한다. 인증 실패가 반복되면 접근을 제한한다. 관리자 접속기록을 남기고 관리자 화면의 출력 항목을 줄인다
- 확인: 평문 저장·로그, 복호화되는 비밀번호, 무제한 로그인 실패, 관리자 API 접속기록 없음
- 경계값:
  - 백엔드: 접속기록 1년 이상 보관(정보주체 5만 명 이상이거나 고유식별정보를 처리하면 2년 이상)
- 근거:
  - 개인정보의 안전성 확보조치 기준 제5조⑥·제7조①②·제8조①·제12조① https://www.law.go.kr/행정규칙/개인정보의안전성확보조치기준
  - 개인정보 보호법 시행령 제30조 — 위 기준의 상위 근거
- 확인하지 못한 것: "가맹점은 카드번호를 저장하면 안 된다"는 명문 조항은 찾지 못했다. 저장 금지 근거는 PCI DSS와 PG 계약이다(`commerce` COM-027). 접속기록 '월 1회 점검'도 현행 고시에 숫자가 없다

## KCL-013 광고 발송은 동의·야간 시간·동의 재확인을 검사한다
- 대상: 백엔드
- 왜: 별도 동의 없이 밤 10시에 광고 푸시가 나간다
- 대신: 발송기가 수신 동의, 야간(21시~다음 날 8시) 별도 동의, 동의일로부터 2년마다 재확인을 검사한다. 이메일은 야간 규정의 예외다. 거래가 끝나고 6개월 안의 같은 종류 상품 광고는 사전 동의 예외다
- 확인: KST 시각·야간 동의를 보지 않는 발송기, 동의일 저장 없음
- 경계값:
  - 백엔드: 20:59·21:00·07:59·08:00(KST), 동의 2년 되는 날
- 근거:
  - 정보통신망법 제50조 https://www.law.go.kr/법령/정보통신망이용촉진및정보보호등에관한법률/제50조
  - 정보통신망법 시행령 제61조·제62조의3
- 확인하지 못한 것: 광고 문자 "(광고)" 표기를 정한 시행령 별표 6 본문

## KCL-014 카드로 결제한다고 금액을 더 붙이지 않는다
- 대상: 백엔드
- 왜: 카드 결제 고객에게만 수수료가 더 붙는다

## 확인하지 못한 것 (전체)

- 부가세 포함 가격 표시 의무: 온라인몰 전반에 적용되는 명문 조항을 찾지 못했다. 가장 가까운 근거는 KCL-006의 총금액 규정이다.
- 청약철회 7일에 민법 기간 계산을 적용하는 것은 조사 에이전트의 해석이다. 공정위 공식 해석은 확인하지 못했다(그래서 설정값 `kcl.periodCounting`으로 둔다).
- 전자금융거래법의 거래기록 보존(5년, 1만 원 이하 1년)은 금융회사·전자금융업자(PG 등)의 의무다. 일반 쇼핑몰에 직접 적용되지 않는다. 자체 포인트를 다른 가맹점에서도 쓰게 하면 선불전자지급수단에 해당하는지 검토가 필요하다.
- 열지 못한 자료: 공정위 다크패턴 가이드라인 첨부 파일, 2025.2.13 다크패턴 문답서 첨부, 정보통신망법 시행령 별표 6, 금융위원회 2014년 보도자료 원문.
