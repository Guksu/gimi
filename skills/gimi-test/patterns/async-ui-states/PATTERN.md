# async-ui-states — 응답의 상태마다 화면 하나

## 언제 쓰는가

서버 응답을 기다렸다가 그리는 화면을 쓰거나 바꿀 때 쓴다. 이런 화면은 상태가 여럿이다. 기다리는 중, 성공, 빈 결과, 처리 중(결제 확인 중·입금 대기), 오류. 결함은 대개 상태를 잘못 묶는 데서 나온다. 처리 중을 성공으로 보이거나, 오류 뒤에 로딩이 영영 안 끝나거나, 빈 결과를 오류로 보인다.

관련 규칙은 `COM-015`(처리 중·입금 대기를 성공으로 취급하지 않는다)다. 응답을 네트워크 경계에서 바꾸는 방법은 [`api-boundary`](../api-boundary/PATTERN.md)를 따른다.

## 무엇을 단언하는가

| 상태 | 보여야 할 것 | 보이면 안 되는 것 |
|---|---|---|
| 기다리는 중 | 진행 중이라는 문구 | 완료 문구 |
| 성공 | 결과(금액·목록), 다음 행동(장바구니 비우기) | 로딩 문구 |
| 처리 중(확인 중·입금 대기) | 기다리라는 문구 | 완료 문구, 완료 때만 하는 일(장바구니 비우기·구매 이벤트) |
| 빈 결과 | 비었다는 문구 | 오류 문구 |
| 오류 | 이유와 다시 할 길(링크·버튼) | 완료 문구, 끝나지 않는 로딩 |

"보이면 안 되는 것"이 핵심이다. 처리 중을 완료로 보이는 결함은 "확인 중 문구가 있다"만으로는 못 잡을 때가 있다.

## 예시

| 파일 | 무엇을 |
|---|---|
| `assets/payment-result.test.tsx` | 좋은 예시 — 결제 결과 화면의 기다리는 중·완료·입금 대기·확인 중(202)·거절(402) |
| `assets/payment-result.slop.test.tsx` | 슬롭 예시 — 성공 응답 하나만 보고, 로딩 문구가 사라졌는지와 제목이 있는지만 본다 |

기다리는 중은 시간을 기다리지 않고 응답을 손으로 놓아준다.

```tsx
let release = () => {}
const answered = new Promise<void>((resolve) => (release = resolve))
confirmAnswers(async () => (await answered, HttpResponse.json(order())))
openAt(RETURN_URL)

expect(screen.getByText('결제를 마무리하고 있어요')).toBeInTheDocument()
expect(screen.queryByRole('heading', { name: '결제가 끝났어요' })).not.toBeInTheDocument()

release()
expect(await screen.findByRole('heading', { name: '결제가 끝났어요' })).toBeInTheDocument()
```

서버가 확인 중(202)이라고 해도 주문을 불러와 완료 화면을 보이게 바꾸면, 좋은 예시는 확인 중 경우에서 실패하고 슬롭 예시는 그대로 통과한다.

## AI가 흔히 쓰는 테스트 / 대신

| 흔히 | 왜 놓치나 | 대신 |
|---|---|---|
| 성공 응답 하나 | 처리 중·오류 화면이 시험되지 않는다 | 상태마다 테스트 하나 |
| `waitFor(() => 로딩이 없다)` 뒤 "제목이 있다" | 어떤 상태로 끝났는지 모른다 | 그 상태의 문구를 이름으로 찾는다(`findByRole('heading', { name })`) |
| `waitFor`의 `timeout`을 늘린다 | 느린 결함을 덮고 테스트가 느려진다 | 응답을 손으로 놓아 기다림을 없앤다 |
| 보여야 할 것만 단언 | 완료 문구가 함께 보이는 결함을 놓친다 | 보이면 안 되는 것도 `queryBy…not.toBeInTheDocument()`로 |
| 로딩 상태를 테스트하지 않는다 | 로딩 중에 완료처럼 보이는 결함을 놓친다 | 응답 전 화면을 먼저 단언한다 |

## Jest와 다른 줄

| Vitest | Jest |
|---|---|
| `findBy…`·`waitFor`(Testing Library) | 같다 — 테스트 도구가 아니라 Testing Library의 API다 |

## 주의사항

- 상태 이름이 아니라 사용자가 보는 문구로 단언한다. 내부 state(`kind === 'checking'`)를 보면 화면이 틀려도 통과한다.
- 처리 중 상태에서는 완료 때만 하는 일(장바구니 비우기·구매 이벤트·알림)이 일어나지 않았는지도 본다.
- 오류에는 다시 할 길이 있어야 한다. 링크의 주소까지 단언한다.
