# regression-first — 고치기 전에 실패하는 테스트부터

## 언제 쓰는가

버그를 고칠 때 쓴다. 고친 뒤에 쓴 테스트는 대개 버그가 나지 않던 조건으로 쓰인다. 그 테스트는 고치기 전 코드에서도 통과해서, 같은 버그가 다시 들어와도 막지 못한다. 재현 테스트를 먼저 쓰고 고치기 전 코드에서 실패하는 것을 보면, 그 테스트가 정말 그 버그를 지킨다는 것이 증명된다.

관련 규칙은 `test/rewritten-expectation`(실패하자 기대값을 고치지 않는다)이다. 리뷰에서는 같은 일을 "이력" 맥락이 한다. 바꾼 줄을 넣은 커밋이 버그 수정이었는지 보고, 새 변경이 그 수정을 되돌리는지 본다.

## 무엇을 단언하는가

| 단언 | 왜 |
|---|---|
| 신고된 조건 그대로의 결과(새벽 1시 배송 → 마감 10월 29일 23:59) | 버그가 나던 바로 그 입력이다 |
| 같은 조건의 끝(새벽의 끝 08:59) | 고친 범위가 조건 전체를 덮는지 본다 |
| 버그가 없던 조건(낮 배송) | 고친 코드가 다른 경우를 깨지 않았는지 본다 |
| 화면에 보이는 값도(마감 시각) | 판정만 고치고 표시는 그대로인 경우를 잡는다 |

그리고 단언 밖의 확인이 하나 있다. **고치기 전 코드에서 이 테스트가 실패하는가.** 실패하지 않으면 재현 테스트가 아니다.

## 예시

| 파일 | 무엇을 |
|---|---|
| `assets/kst-day-regression.test.ts` | 좋은 예시 — 새벽 1시·새벽의 끝 08:59 배송의 반품 기한, 화면 마감, 버그가 없던 낮 배송 |
| `assets/kst-day-regression.slop.test.ts` | 슬롭 예시 — 고친 뒤에 낮 배송으로만 쓴 테스트. 고치기 전 코드에서도 통과한다 |

신고의 조건을 테스트 이름과 입력에 그대로 옮긴다. 한국 시간 새벽은 UTC로 전날이라 날짜 경계 버그가 여기서만 난다.

```ts
it('10월 22일 01:00(KST)에 받으면 10월 29일 23:59(KST)까지 반품을 받는다', async () => {
  const id = await deliveredAt('2026-10-21T16:00:00.000Z')
  t.clock.set('2026-10-29T14:59:59.999Z')
  expect((await requestReturn(id)).status).toBe(201)
})
```

고치기 전 코드에서 실패하는지는 이렇게 본다.

```bash
git stash push -- src/   # 고친 코드만 잠깐 치운다(테스트는 남긴다)
npx vitest run test/kst-day-regression.test.ts   # 실패해야 한다
git stash pop
```

받은 날 0시를 "한 줄로 정리"하면서 날짜를 구하기 전의 한국 시간 처리를 지우면(예전 수정을 되돌림), 좋은 예시는 새벽 배송 경우들에서 실패하고 슬롭 예시는 그대로 통과한다.

## AI가 흔히 쓰는 테스트 / 대신

| 흔히 | 왜 놓치나 | 대신 |
|---|---|---|
| 고친 뒤에 통과하는 테스트만 쓴다 | 고치기 전에도 통과하면 버그를 지키지 못한다 | 고치기 전 코드에서 실패를 먼저 본다 |
| 신고와 다른 조건(낮 배송)으로 쓴다 | 버그가 나던 입력이 시험되지 않는다 | 신고의 조건을 그대로 |
| 실패하자 기대값을 지금 결과로 고친다 | 버그를 기대값으로 굳힌다 | 기대값은 요구사항·신고에서 가져온다 |
| 재현 테스트만 쓴다 | 고친 코드가 다른 경우를 깨도 모른다 | 버그가 없던 조건도 한 줄 |
| 테스트 이름에 버그 내용이 없다 | 나중에 지워도 되는 테스트처럼 보인다 | 이름에 신고된 조건을 적는다 |

## Jest와 다른 줄

다른 줄이 없다.

## 주의사항

- 재현이 안 되면 고치지 않는다. 먼저 조건을 더 좁힌다(시간대·데이터·순서). 재현 없이 고친 코드는 무엇을 고쳤는지 증명할 수 없다.
- 커밋 메시지에 버그와 재현 조건을 적는다. 나중에 같은 줄을 바꾸는 사람(과 리뷰의 이력 맥락)이 이 테스트의 이유를 찾는다.
- `check.mjs --baseline`은 실패한 명령을 기준(갈림점)의 코드에서 다시 돌린다. 재현 테스트를 먼저 커밋해 두면 "기준에서도 실패"로 재현을 보일 수 있다.
