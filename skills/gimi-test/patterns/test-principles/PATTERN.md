# test-principles — 무엇을, 어디까지 실물로, 어떤 이름으로

## 언제 쓰는가

테스트를 쓰기 시작할 때, 그리고 다른 패턴이 맞지 않을 때 바탕으로 쓴다. AI가 쓴 테스트의 결함은 대개 이 단계에서 정해진다. 구현의 조각 하나를 떼어 내고 나머지를 전부 mock하면, 테스트는 mock에 넣은 값을 다시 계산해 볼 뿐이다. 조각과 조각이 이어지는 곳(요청 → 저장 → 외부 호출)의 결함은 아무도 보지 않는다.

관련 규칙은 `test/mock-subject`(테스트 대상 모듈을 통째로 mock하지 않는다), `test/mock-echo`(mock이 돌려준 값을 그대로 단언하지 않는다), `COM-003`(결제 금액은 서버가 계산·저장)이다.

## 무엇을 단언하는가

정하는 순서는 이렇다.

1. **무엇을 지킬지.** 요구사항·규칙의 문장 하나를 고른다("결제 금액은 서버가 계산하고 저장한 값만 PG에 보낸다"). 구현의 함수 하나가 아니다.
2. **어디서 볼지.** 그 문장이 지켜지는지 보이는 가장 바깥에서 본다. 백엔드는 API 요청 → 응답·DB·외부 호출, 프론트는 화면의 조작 → 보이는 결과다.
3. **무엇을 가짜로.** 경계 밖만 바꾼다. 아래 표를 따른다.

| 대상 | 기본 | 이유 |
|---|---|---|
| 테스트할 코드와 그 안쪽 모듈 | 실물 | 이어지는 곳의 결함이 여기서 난다 |
| DB | 실물(테스트 전용) | 조건·제약을 DB가 지킨다([`db-integration`](../db-integration/PATTERN.md)) |
| 외부 API(PG·배송·알림) | fake — 가짜 HTTP 서버·MSW | 실패 응답을 마음대로 만든다([`external-api-fake`](../external-api-fake/PATTERN.md)·[`api-boundary`](../api-boundary/PATTERN.md)) |
| 시계·난수 | 주입해 고정 | 날마다 결과가 바뀌지 않게([`fake-time`](../fake-time/PATTERN.md)) |
| 보내기만 하는 부수효과(분석 이벤트·로그) | spy로 듣기 | 무엇을 보냈는지 센다 |

mock(호출을 기록하고 정해 둔 값을 돌려주는 가짜)은 위로 안 될 때만 쓴다. 쓰면 "무엇을 보냈는가"를 단언하고, mock이 돌려준 값은 단언하지 않는다.

4. **이름과 자리.** 테스트 이름은 지키는 문장이다. 파일은 대상 옆(`cart.test.ts`)이나 프로젝트의 테스트 폴더에 둔다. 본문은 준비 → 실행 → 단언 순서로, 빈 줄로 나눈다.

## 예시

| 파일 | 무엇을 |
|---|---|
| `assets/order-amount.test.ts` | 좋은 예시 — "주문 금액은 서버가 계산한다"를 주문 API의 바깥에서 본다. 요청의 금액은 무시되고, 저장·PG가 받은 금액이 서버의 계산과 같은지 |
| `assets/order-amount.slop.test.ts` | 슬롭 예시 — 금액 계산 조각만 떼어 DB를 mock한다. 주문이 화면의 총액을 저장해도 통과한다 |

```ts
it('결제창은 저장한 금액으로 연다 — PG가 받은 금액도 15,000원이다', async () => {
  const { paymentKey } = await orderWithCheckout(t, { total: 100 })

  expect(t.pg.payments.get(paymentKey)?.totalAmount).toBe(15000)
})
```

주문 요청에 화면의 총액(`total`)이 오면 그 금액으로 주문하게 바꾸면, 좋은 예시는 요청에 금액을 넣은 경우들에서 실패하고 슬롭 예시는 그대로 통과한다.

## AI가 흔히 쓰는 테스트 / 대신

| 흔히 | 왜 놓치나 | 대신 |
|---|---|---|
| 모든 import를 `vi.mock` | 테스트가 mock끼리의 대화만 본다 | 경계 밖만 가짜, 안쪽은 실물 |
| 구현의 함수 하나를 떼어 테스트 | 조각이 이어지는 곳의 결함을 놓친다 | 요구사항이 보이는 가장 바깥에서 |
| mock이 돌려준 값을 단언 | mock에 넣은 값을 다시 읽을 뿐이다 | 대상이 만든 결과·보낸 것을 단언 |
| 테스트 이름이 함수 이름(`quote()`) | 무엇을 지키는지 모른다 | 지키는 문장 |
| 정상 요청만 보낸다 | 이상한 요청(금액 필드·남의 ID)을 시험하지 않는다 | 바꿔 보낼 수 있는 값을 일부러 넣는다 |

## Jest와 다른 줄

| Vitest | Jest |
|---|---|
| `vi.mock`·`vi.fn`·`vi.spyOn` | `jest.mock`·`jest.fn`·`jest.spyOn` — 기준은 같다 |

## 주의사항

- "단위 테스트라서 mock한다"는 기준이 아니다. 단위는 지키는 행동 하나이고, 그 행동이 걸친 코드는 실물로 둔다.
- 느린 것(실제 DB)은 테스트 전용으로 빠르게 만든다(비우기·시드). 느리다고 mock으로 바꾸면 그 DB가 지키던 규칙이 시험에서 빠진다.
- 테스트를 다 쓴 뒤 [`test-audit`](../test-audit/PATTERN.md)의 규칙표로 슬롭이 없는지 본다.
