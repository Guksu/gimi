# state-transition — 허용·금지 쌍을 모두, 늦게 온 이벤트까지

## 언제 쓰는가

주문·결제·배송처럼 **상태가 있는 것**의 전이를 쓰거나 바꿀 때 쓴다. 상태 전이는 성공 경로만 따라가면 늘 통과한다. 사고는 막아야 하는 전이에서 난다. 취소한 주문이 늦게 온 승인으로 결제 완료가 되고, 배송을 시작한 주문이 취소된다. 웹훅은 순서를 보장하지 않으니 늦게 온 이벤트도 막아야 한다.

관련 규칙은 `COM-013`(주문 상태는 전이 함수에서만 바꾸고, 되돌아가는 전이도 전이표에 넣는다)이다. 경계값은 `node <이 스킬 폴더>/scripts/rules.mjs --id COM-013`에서 가져온다.

## 무엇을 단언하는가

| 단언 | 왜 |
|---|---|
| 모든 (지금 상태, 다음 상태) 쌍이 허용·금지 중 기대한 쪽이다 | 허용한 쌍만 보면 새로 열린 전이를 놓친다 |
| 기대 표는 요구사항에서 옮겨 테스트에 따로 적는다 | 구현의 표를 가져와 비교하면 구현이 틀려도 같이 틀린다 |
| 되돌아가는 전이(실패 → 승인, 완료 → 입금 대기)도 표에 있다 | 실제로 오는 이벤트다. 막으면 돈은 받았는데 주문은 실패로 남는다 |
| 끝난 상태(취소·배송 완료)에 늦게 온 이벤트가 상태와 재고·포인트를 바꾸지 않는다 | 표가 맞아도 이벤트 처리가 표를 거치지 않으면 새어 나간다 |

## 예시

| 파일 | 무엇을 |
|---|---|
| `assets/order-state.test.ts` | 좋은 예시 — 9개 상태의 81쌍을 `it.each`로 하나씩 보고, 취소한 주문에 PG 승인이 늦게 와도 취소 그대로인지 본다 |
| `assets/order-state.slop.test.ts` | 슬롭 예시 — 결제 대기 → 결제 완료 → 배송 준비 성공 경로만 본다. 취소한 주문이 되살아나도 통과한다 |

쌍마다 테스트 하나로 펼치면 실패한 쌍이 이름으로 보인다.

```ts
const PAIRS = STATUSES.flatMap((from) => STATUSES.map((to) => [from, to, ALLOWED[from].includes(to)] as const))

it.each(PAIRS)('%s → %s 허용: %s', (from, to, allowed) => {
  expect(canTransition(from, to)).toBe(allowed)
})
```

전이표에 취소 → 결제 완료를 더하면 좋은 예시는 `cancelled → paid 허용: false`와 늦게 온 승인 테스트에서 실패하고, 슬롭 예시는 그대로 통과한다.

## AI가 흔히 쓰는 테스트 / 대신

| 흔히 | 왜 놓치나 | 대신 |
|---|---|---|
| 성공 경로 하나를 따라간다 | 막아야 하는 전이를 시험하지 않는다 | 모든 쌍을 표로 본다 |
| 허용한 전이만 나열해 본다 | 새로 열린 금지 전이를 놓친다 | 금지 쌍도 하나씩 `false`인지 본다 |
| 구현의 전이표를 import해 그대로 비교한다 | 구현이 틀리면 테스트도 같이 틀린다 | 기대 표를 요구사항에서 옮겨 테스트에 적는다 |
| 이벤트를 순서대로만 보낸다 | 웹훅은 늦게·거꾸로 온다 | 끝난 상태 뒤에 늦은 이벤트를 보낸다 |
| 상태 값만 본다 | 전이가 막혀도 재고·포인트를 먼저 바꿨을 수 있다 | 상태와 함께 그 전이가 건드리는 값을 본다 |

## Jest와 다른 줄

다른 줄이 없다. `it.each`는 Jest에서도 같다.

## 주의사항

- 상태가 많으면 쌍이 많아진다(9개면 81쌍). 표가 길어도 쌍을 줄이지 않는다. 사고는 줄인 쌍에서 난다.
- 화면의 상태별 버튼·배지는 서버가 준 값(취소 가능 여부 등)으로 정한다. 프론트 테스트는 [`async-ui-states`](../async-ui-states/PATTERN.md)처럼 상태마다 하나씩 본다.
- 같은 이벤트가 두 번 오는 경우는 [`idempotency`](../idempotency/PATTERN.md), 서명·모르는 type은 [`webhook-contract`](../webhook-contract/PATTERN.md)로 본다.

## 다른 언어

| 언어 | 모든 쌍 펼치기 |
|---|---|
| Java·Kotlin | JUnit `@ParameterizedTest` + `@MethodSource`(enum 두 개의 곱) |
| Python | `pytest.mark.parametrize`와 `itertools.product` |
| Go | 표 주도 테스트(`for _, from := range statuses { for _, to := range statuses { t.Run(...) } }`) |
