# webhook-contract — 웹훅은 아무나 보낼 수 있다고 보고 테스트한다

## 언제 쓰는가

결제 완료·입금·환불을 알리는 웹훅(외부 서비스가 우리 서버로 보내는 HTTP 요청)의 핸들러를 쓰거나 바꿀 때 쓴다. 웹훅 주소는 공개돼 있다. 누구나 요청을 보낼 수 있고, PG도 같은 이벤트를 다시 보내거나 순서를 바꿔 보낸다. 정상 이벤트 하나로는 이런 경우가 하나도 시험되지 않는다.

관련 규칙은 `COM-021`(웹훅 본문을 믿지 않는다)과 `COM-022`(웹훅 처리는 멱등하고 순서와 무관)다. 경계값은 `node <이 스킬 폴더>/scripts/rules.mjs --id COM-021`에서 가져온다.

## 무엇을 단언하는가

| 보내는 웹훅 | 단언 |
|---|---|
| 서명이 틀리거나 없음 | 401, 주문은 그대로 |
| 서명은 맞지만 본문의 상태가 실제(PG 조회)와 다름 | 주문은 실제 상태를 따른다. 본문의 "결제 완료"로 바뀌지 않는다 |
| 같은 이벤트 두 번 | 두 번째도 200(오류로 답하면 PG가 계속 다시 보낸다), 처리 기록은 하나 |
| 순서가 바뀐 옛 이벤트 | 지금 상태(취소 등)를 지킨다 |
| 모르는 type | 200, 아무것도 바꾸지 않는다 |

## 예시

| 파일 | 무엇을 |
|---|---|
| `assets/pg-webhook.test.ts` | 좋은 예시 — 위 다섯 경우를 테스트가 직접 서명한 웹훅으로 보낸다 |
| `assets/pg-webhook.slop.test.ts` | 슬롭 예시 — 가상계좌 입금 웹훅(정상 이벤트) 하나만 본다. 본문을 그대로 믿는 핸들러도 통과한다 |

웹훅은 테스트가 만든다. 서명은 PG와 같은 방식으로 붙이고, 틀린 서명과 실제와 다른 본문은 일부러 만든다.

```ts
const send = (event: unknown, signature?: string) => {
  const raw = JSON.stringify(event)
  return request(t.app.getHttpServer())
    .post('/webhooks/pg')
    .set('x-fakepg-signature', signature ?? signWebhook(KEYS.webhookSecret, raw))
    .send(raw)
}

// 서명은 맞지만 본문의 상태가 PG의 지금 상태(READY)와 다르다
await send(statusChanged(paymentKey, order.id, 'DONE'))
expect(await statusOf(order.id)).toBe('pending_payment')
```

서명은 원문 본문으로 계산한다. 테스트가 객체를 보내고 서버가 JSON을 다시 만들어 서명을 비교하면, 공백 하나로 서명이 달라진다. 그래서 문자열(`raw`)을 보낸다.

웹훅마다 PG를 조회하지 않고 본문의 상태로 바로 반영하게 바꾸면, 좋은 예시는 위조 본문에서 주문이 결제 완료가 되어 실패하고, 슬롭 예시는 그대로 통과한다.

## AI가 흔히 쓰는 테스트 / 대신

| 흔히 | 왜 놓치나 | 대신 |
|---|---|---|
| 정상 이벤트 하나 | 위조·중복·역순이 시험되지 않는다 | 다섯 경우를 한 묶음으로 |
| 서명 검증 함수를 mock해 늘 참 | 서명 검증이 빠져도 통과한다 | 진짜 비밀값으로 서명하고, 틀린 서명도 보낸다 |
| 본문의 상태가 실제와 같은 이벤트만 | 본문을 믿는 핸들러를 가려내지 못한다 | 실제(PG)는 승인 전인데 본문만 결제 완료인 이벤트 |
| 중복 이벤트에 4xx를 기대 | 오류로 답하면 PG가 계속 다시 보낸다 | 200과 처리 기록 하나 |
| 핸들러 함수를 직접 부른다 | 원문 본문·서명 머리·라우트 앞의 파서가 빠진다 | HTTP로 보낸다(supertest) |

## Jest와 다른 줄

다른 줄이 없다. supertest는 Jest에서도 같다.

## 주의사항

- 원문 본문이 필요하다. 웹훅 라우트 앞에서 전역 JSON 파서가 본문을 객체로 바꾸면 서명을 검증할 원문이 사라진다. 테스트가 이것도 잡는다.
- 서명에 시각이 들어가면(허용 오차) 시계를 고정하고, 허용 오차를 넘긴 요청도 보낸다.
- 처리 결과는 처리 기록 표(이벤트 ID 유니크)로 본다. 응답만 보면 중복 처리를 놓친다([`idempotency`](../idempotency/PATTERN.md)).

## 다른 언어

| 언어 | 웹훅 보내기 | 서명 |
|---|---|---|
| Java·Kotlin | MockMvc로 원문 문자열을 본문에 | `Mac.getInstance("HmacSHA256")` |
| Python | 테스트 클라이언트에 `data=raw` | `hmac.new(secret, raw, sha256)` |
| Go | `httptest.NewRequest`에 원문 | `crypto/hmac` |
