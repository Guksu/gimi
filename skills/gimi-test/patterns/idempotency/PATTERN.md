# idempotency — 같은 일이 다시 와도 부수효과는 한 번

## 언제 쓰는가

주문 생성·결제 확정·환불처럼 **다시 불릴 수 있는 작업**을 쓰거나 바꿀 때 쓴다. 같은 작업은 생각보다 자주 다시 온다. 손님은 새로고침하고, 앱은 타임아웃 뒤 재시도하고, PG는 확정 요청과 별개로 웹훅을 보낸다. 작업이 멱등하지 않으면(다시 해도 결과가 같지 않으면) 주문이 두 번 생기고 포인트가 두 번 쌓인다.

관련 규칙은 `COM-018`(확정 처리는 여러 번 불려도 한 번만 반영)과 `COM-016`(결제 요청은 한 번)이다. 경계값은 `node <이 스킬 폴더>/scripts/rules.mjs --id COM-018`에서 가져온다.

## 무엇을 단언하는가

| 단언 | 왜 |
|---|---|
| 두 번째 응답이 첫 번째와 같은 결과다(같은 주문 ID, 같은 상태) | 다시 보낸 쪽은 결과만 알면 된다 |
| 만들어진 행 수(주문·결제 기록)가 1이다 | 응답은 같아도 행이 둘일 수 있다 |
| 잔액·재고·포인트 같은 숫자가 한 번만 바뀌었다 | 가장 흔히 새는 부수효과다 |
| 비동기로 오는 것(웹훅)까지 처리된 뒤에 센다 | 웹훅이 늦게 와서 두 번째 반영이 테스트가 끝난 뒤에 일어날 수 있다 |

## 예시

| 파일 | 무엇을 |
|---|---|
| `assets/payment-once.test.ts` | 좋은 예시 — 같은 멱등 키로 주문 재전송, 결제 확정 재전송, 확정 요청과 웹훅이 겹침, 동시 확정 두 번. 모두 부수효과를 센다 |
| `assets/payment-once.slop.test.ts` | 슬롭 예시 — 같은 확정을 두 번 보내고 응답만 본다. 포인트가 두 번 쌓여도 통과한다 |

부수효과를 한곳에서 세는 함수를 두면 경우마다 같은 기준으로 본다.

```ts
const effects = async () => ({
  orders: await one('SELECT count(*)::int AS n FROM orders'),
  payments: await one('SELECT count(*)::int AS n FROM payments'),
  points: await one('SELECT points AS n FROM users WHERE id = 1'),
})

await confirm(order.id, paymentKey, order.total)
await t.pg.flushWebhooks() // 가짜 PG가 보낸 웹훅까지 처리된 뒤에
expect(await effects()).toMatchObject({ payments: 1, points: 5150 })
```

`flushWebhooks`는 가짜 PG가 보낸 웹훅이 모두 처리될 때까지 기다리는 도우미다. 프로젝트에 없으면 웹훅을 테스트에서 직접 보내고 응답을 기다린다.

결제 완료를 반영할 때마다 포인트를 쌓도록 바꾸면 좋은 예시는 확정과 웹훅이 겹친 경우에서 포인트가 5,300이 되어 실패하고, 슬롭 예시는 그대로 통과한다.

## AI가 흔히 쓰는 테스트 / 대신

| 흔히 | 왜 놓치나 | 대신 |
|---|---|---|
| 한 번 호출하고 성공만 본다 | 다시 오는 경우를 시험하지 않는다 | 같은 요청을 두 번, 그리고 동시에 두 번 |
| 두 번 보내고 응답 코드만 본다 | 응답은 둘 다 200이어도 부수효과는 두 번일 수 있다 | 행 수와 숫자(잔액·재고·포인트)를 센다 |
| 웹훅을 빼고 확정 요청만 본다 | 실제로는 확정 요청과 웹훅이 같은 결제를 따로 반영한다 | 두 경로가 겹친 뒤에 센다 |
| 비동기 처리를 기다리지 않고 바로 센다 | 두 번째 반영이 단언 뒤에 일어나 통과한다 | 웹훅·큐가 다 처리된 뒤에 센다(도우미로 기다린다) |
| 멱등 키를 테스트마다 새로 만든다 | "같은 키"를 시험하지 않는다 | 한 테스트 안에서 같은 키를 두 번 쓴다 |

## Jest와 다른 줄

다른 줄이 없다. supertest와 `Promise.all`은 Jest에서도 같다.

## 주의사항

- 멱등 키는 같고 본문이 다른 재전송도 생각한다. 다른 결과를 조용히 돌려주는지, 오류로 알리는지 규칙(`COM-016`)에 맞춰 단언한다.
- 서버를 다시 띄워도 멱등해야 한다면 처리 기록은 메모리가 아니라 DB(유니크 제약)에 있어야 한다. 테스트도 실제 DB로 돌린다.
- 동시 두 번은 [`concurrency`](../concurrency/PATTERN.md)와 같은 방식으로 `Promise.all`로 보낸다.

## 다른 언어

| 언어 | 같은 요청 다시 보내기 | 부수효과 세기 |
|---|---|---|
| Java·Kotlin | MockMvc·WebTestClient로 같은 요청 두 번 | JdbcTemplate로 행 수·잔액 조회 |
| Python | 테스트 클라이언트로 두 번 | 테스트 DB 세션으로 조회 |
| Go | `httptest`로 두 번 | `database/sql`로 조회 |
