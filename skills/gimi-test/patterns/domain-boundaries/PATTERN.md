# domain-boundaries — 규칙의 경계 바로 안과 바로 밖

## 언제 쓰는가

금액·수량·기간처럼 **규칙이 숫자로 선을 긋는 코드**를 쓰거나 바꿀 때 쓴다. 결함은 대개 선 위에 있다. `<`와 `<=`, 받은 날을 세는지, 날짜 경계를 어느 시간대로 잡았는지, 할인 뒤 금액이 0원 밑으로 내려가는지 같은 것이다. 정상값 하나는 이런 결함을 지나친다.

경계값은 지어내지 않고 규칙에서 가져온다.

```bash
node <이 스킬 폴더>/scripts/rules.mjs --boundaries
```

분야 프리셋(`commerce`·`kr-commerce-law`)과 회사 규칙(`docs/gimi/rules.md`)의 "경계값" 가운데 이 프로젝트의 층(설정 `stacks`)에 맞는 것이 나온다. 규칙에 경계값이 없으면 0·1·최대·최대 + 1, 빈 값, 같은 요청 두 번을 넣는다.

## 무엇을 단언하는가

| 단언 | 왜 |
|---|---|
| 경계 바로 안(허용하는 마지막 값)은 통과한다 | 기한·한도를 하루·1원 줄인 결함을 잡는다 |
| 경계 바로 밖(막는 첫 값)은 막힌다 | 기한·한도를 늘린 결함을 잡는다 |
| 경계의 기준(날짜 경계의 시간대, 받은 날을 세는지) | 같은 규칙을 두 곳에서 다르게 계산한 결함을 잡는다 |
| 화면에 보이는 값과 판정 경계가 같다 | "10월 28일까지"라고 보이는데 그 전에 막는 결함을 잡는다 |

## 예시

| 파일 | 무엇을 |
|---|---|
| `assets/return-window.test.ts` | 좋은 예시 — 청약철회 기한(KCL-001)의 7일째 23:59:59.999 허용·8일째 00:00 차단, 밤늦게 받은 주문, 화면의 마감과 판정, 상품 하자 90일 |
| `assets/return-window.slop.test.ts` | 슬롭 예시 — 배송 3일 뒤 허용, 한 달 뒤 차단. 기한이 하루 짧거나 시각 기준이 틀려도 통과한다 |

경계 한 쌍을 표의 이웃한 줄로 둔다. 시각은 UTC로 적고 옆에 한국 시간을 단다. 예시의 `t.clock`은 앱에 주입한 고정 시계다.

```ts
it.each([
  { when: '7일째(10월 28일) 23:59:59.999', now: '2026-10-28T14:59:59.999Z', status: 201 },
  { when: '8일째(10월 29일) 00:00', now: '2026-10-28T15:00:00.000Z', status: 409 },
])('단순 변심 — $when → $status', async ({ now, status }) => {
  const id = await deliveredAt(DELIVERED)
  t.clock.set(now)
  expect((await requestReturn(id, 'change_of_mind')).status).toBe(status)
})
```

반품 기한을 배송 시각 + 7×24시간으로 따로 계산하게 바꾸면 좋은 예시는 7일째 저녁의 반품이 막혀 실패하고, 슬롭 예시는 그대로 통과한다.

프론트에서도 같다. 수량 입력의 1·상한·상한 + 1, 무료 배송 기준 금액의 1원 아래와 정확히 기준을 표로 넣고, 화면에 보이는 결과(안내 문구·버튼 상태)를 단언한다.

## AI가 흔히 쓰는 테스트 / 대신

| 흔히 | 왜 놓치나 | 대신 |
|---|---|---|
| 정상값 하나(배송 3일 뒤 반품 허용) | 경계가 하루 어긋나도 3일째는 허용이다 | 마지막 허용 값과 첫 차단 값을 한 쌍으로 |
| 기대값을 테스트 안에서 다시 계산 | 구현과 같은 실수를 테스트도 한다 | 규칙에서 옮긴 값을 그대로 적는다 |
| `new Date()`로 현재 시각 기준 | 날마다 다른 경계를 시험하고 가끔 깨진다 | 주입한 시계를 고정한다 |
| 여러 경계를 한 테스트에 이어서 확인 | 앞 단언이 깨지면 뒤 경계는 시험되지 않는다 | `it.each`로 줄마다 따로 실패하게 |
| 경계 한 쌍을 하루 차이로 둔다 | 시각 기준이 틀린 결함을 지나친다 | 1ms·1원·1개 차이로 |

## Jest와 다른 줄

| Vitest | Jest |
|---|---|
| `it.each([{ … }])('… $when', …)` | 같다. 객체 배열과 `$이름` 끼워 넣기를 둘 다 쓴다 |
| 주입한 시계 대신 `vi.setSystemTime` | `jest.setSystemTime`(가짜 타이머를 켠 뒤) |

## 주의사항

- 해석이 들어간 경계(민법 기간 계산, 영업일)는 팀이 정한 값(`kcl.periodCounting`·`kcl.businessDays`)을 쓴다. 정하지 않았으면 테스트로 굳히기 전에 묻는다.
- 시간대를 바꿔도 결과가 같아야 한다. CI의 `TZ`가 달라 깨지면 코드가 서버의 시간대에 기대고 있다는 뜻이다.
- 경계값의 출처(규칙 ID)를 테스트 이름이나 주석에 단다. 규칙이 바뀌면 어느 표를 고칠지 찾을 수 있다.
