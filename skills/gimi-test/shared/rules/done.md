# 완료 보고 금지선 — `done/`

작업을 끝내며 보고할 때 AI가 흔히 하는 슬롭이다. 끝내기 전 검사(`scripts/check.mjs`)의 출력이 대부분을 막는다. 형식은 `test.md`와 같다.

- `검사`의 "출력"은 check.mjs가 보고에 그 줄을 내 준다는 뜻이다. 에이전트는 그 줄을 그대로 붙인다.

## done/unrun-claim 실행하지 않고 "통과했어요"라고 하지 않는다
- 대상: 둘 다
- 왜: 확인하지 않은 것을 확인했다고 믿게 한다
- 대신: 실행한 명령·종료 코드·결과 수를 붙인다
- 확인: 보고에 check.mjs의 명령·결과 줄이 없다
- 검사: 출력(check.mjs가 명령·종료 코드·결과 수를 낸다)
- 근거: 측정 2026-10-27 — 셀 수 없었다: 대화 기록을 남기지 않아 에이전트가 실제로 어떤 명령을 돌렸는지 알 수 없다 — 보고만으로는 판정할 근거가 없다

## done/partial-run 일부만 돌리고 전체가 통과한 것처럼 말하지 않는다
- 대상: 둘 다
- 왜: 돌리지 않은 곳의 실패를 숨긴다
- 대신: 바뀐 범위와 돌리지 않은 것을 적는다
- 확인: 보고에 범위(관련 테스트만·전체)와 건너뜀 줄이 없다
- 검사: 출력(check.mjs가 범위와 건너뜀을 낸다)
- 근거: 측정 2026-10-27 — 셀 수 없었다: 대화 기록을 남기지 않아 에이전트가 실제로 어떤 명령을 돌렸는지 알 수 없다 — 보고만으로는 판정할 근거가 없다

## done/blamed-preexisting 실패를 확인 없이 "원래 있던 실패"로 넘기지 않는다
- 대상: 둘 다
- 왜: 이 변경이 만든 실패가 남는다
- 대신: 기준(갈림점)에서 같은 명령을 돌려 보고 결과를 적는다
- 확인: 기준 결과 없이 "원래 있던 실패", "이 변경과 무관"이라고 한다
- 검사: 출력(check.mjs --baseline이 기준 줄을 낸다)
- 근거: 측정 2026-10-27 — 셀 수 없었다: 대화 기록을 남기지 않아 에이전트가 실제로 어떤 명령을 돌렸는지 알 수 없다 — 보고만으로는 판정할 근거가 없다

## done/skipped-checks 타입 검사·린트를 말없이 건너뛰지 않는다
- 대상: 둘 다
- 왜: 돌리지 않은 검사를 통과한 것으로 읽는다
- 대신: 건너뜀 + 이유를 적는다
- 확인: 보고에 건너뜀 줄이 없다
- 검사: 출력(check.mjs가 건너뜀과 이유를 낸다)
- 근거: 측정 2026-10-27 — 셀 수 없었다: 대화 기록을 남기지 않아 에이전트가 실제로 어떤 명령을 돌렸는지 알 수 없다 — 보고만으로는 판정할 근거가 없다

## done/test-bent 통과시키려고 테스트를 고치거나 건너뛰게 했다면 보고에 밝힌다
- 대상: 둘 다
- 왜: 테스트가 지키던 것을 말없이 풀어 준다

- 근거: 측정 2026-10-27 — gimi 없이 24번 중 0번 · gimi 있이 24번 중 0번
